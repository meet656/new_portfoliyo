Project Overview

ServiceHub is a web platform for finding local service providers in Ahmedabad — electricians, plumbers, AC repair, painters, carpenters, pest control, home cleaning and tutors. Customers search and filter listings by category, locality, rating and price, then call the provider, message them on WhatsApp, or send a booking request.

Providers sign up as Service Partners, manage their business profile and listings, and handle the bookings that come in. Admins review listings, manage users and see an audit log of sensitive actions.

It is a single Flask application: a JSON API under /api that also serves a static HTML and vanilla-JavaScript frontend, installable as a Progressive Web App.

Objectives

  1. Make it quick to find a provider for a specific service in a specific part of the city.
  2. Let customers contact or book a provider directly, without a middleman.
  3. Give providers a free way to list their business and manage bookings.
  4. Show ratings and verification honestly, so listings can be trusted.
  5. Keep accounts secure and the platform easy to run in production.

Problem & Solution

The problem

Finding a reliable electrician, plumber or tutor nearby usually means asking around or scrolling through scattered listings with little detail. It is hard to compare providers by area, price and rating in one place, and small local providers have few simple ways to be found online.

The solution

A single directory organised by service category and city locality. Customers can browse without an account, search and filter, use their location to match the nearest area, and contact or book a provider once signed in. Providers get a free partner account with their own dashboard, and admins get the tools to keep listings accurate.

Key Features

Search & Filters

Search names, descriptions, categories and locations, and filter by category, subcategory, area, rating and price.

Area-Aware Discovery

“Use my location” matches you to the nearest locality. When an area has few results, the list widens to neighbouring localities.

Call, WhatsApp & Booking

Signed-in users can call or WhatsApp a provider, or send a booking request with a preferred date, time and notes.

Honest Ratings & Reviews

Shows the site’s own reviews, otherwise Google’s score labelled as Google’s, otherwise “No ratings yet”. One review per user per listing.

Partner Dashboard

Providers manage a business profile and their listings, accept or decline bookings, and see their earnings and reviews.

Admin Panel

Overview stats, listing search and editing, deactivate and restore, user management, referrals and an audit log.

Secure Accounts

Email one-time-code verification at signup, code-based password reset, and short-lived JWT sessions with rotating refresh tokens.

Installable PWA

A web app manifest and service worker make it installable, cache the app shell for fast repeat visits and show an offline fallback.

SEO-Ready Pages

Clean URLs for every listing and provider, category and area landing pages, a live sitemap.xml, robots.txt and per-page metadata.

How a request flows through ServiceHub

  1. Browser

    Static HTML pages and vanilla JavaScript call the API with fetch. A service worker caches the app shell.

  2. Nginx

    Terminates HTTPS in front of the application server.

  3. Gunicorn + Flask

    App factory with API blueprints, JWT auth, rate limits, security headers and the SEO module. Runs pending migrations on start.

  4. PostgreSQL

    Users, listings, bookings, reviews, areas and audit log, managed through versioned SQL migrations.

External services: Google Places API (listing data and photos, called server-side), SMTP for one-time codes, and optional Google Tag Manager for analytics.

Key Challenges & Solutions

Ratings people can trust

Challenge Most listings came from Google and had no reviews on the site. An audit found the early UI filled the gap with placeholder ratings and labelled every listing “Verified”.

Solution Ratings now come from real site reviews, then Google’s score clearly labelled, then “No ratings yet”. The verified badge appears only after an admin verifies a listing, and a CLI command recomputes cached ratings from real reviews.

Secure password reset and sessions

Challenge Reset links could take their host from a forwarded header, old refresh tokens kept working after a password change, and codes could be re-requested to get more guesses.

Solution Links are built only from the configured site URL, and production refuses to boot without one. Codes are emailed, stored as HMACs and rate limited per account, and a password change revokes every earlier token.

Moving from SQLite to PostgreSQL

Challenge A SQLite file on a hosted server can be wiped on restart, and running a local command against the production database was too easy.

Solution One database layer supports both engines with separate migration sets and connection pooling. Write commands refuse a remote database unless explicitly confirmed, and a config check warns about it.

Thin results in some areas

Challenge Coverage varies by locality, so searching a smaller area could return almost nothing.

Solution Localities store their neighbours. When an area has fewer than five matches, results are topped up from adjacent localities, while well-covered areas still cost a single query.

Stale caches after deploys

Challenge The service worker could keep serving old JavaScript after an update, and one cross-origin font made the whole pre-cache fail under the site’s strict Content Security Policy.

Solution The cache version is bumped with every app-shell change so returning visitors get matching files, and the web fonts are self-hosted.

Importing listings without duplicates

Challenge Adding researched providers in bulk risked duplicate or badly categorised listings.

Solution The importer previews first, validates every record against the category and area lists, rejects matches by phone, email, website or name and address, backs up the database, then reads new rows back through the API.
