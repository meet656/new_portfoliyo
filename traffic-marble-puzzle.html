Project Overview

Traffic Marble Puzzle is a color-matching puzzle game about cars, marbles and getting the order right. A chain of colored marbles rolls around a track. In the middle sits a small parking grid full of cars. Tap a car and it drives off in the direction of its arrow to meet the marble chain.

Hit a marble of the same color and it breaks. Hit the wrong color and the car comes back, costing a heart. Cars can block each other, so the order you move them in matters. Clear every car before the marbles reach the end of the track.

The app is a single Android app where Flutter and Godot each do one job: Flutter runs the menus, level select, settings and saving, and the embedded Godot engine runs the game itself.

How to play

  1. Tap a car — it drives toward the marble track.
  2. Match it with a marble of the same color to break it.
  3. A wrong color sends the car back and costs one heart.
  4. Clear all the cars to complete the level and earn up to 3 stars.
  5. Lose all three hearts, or let the marbles reach the end, and it’s game over.

Key Features

Android Mobile Game

Portrait, one-tap controls built for phones, with pause, music and sound switches, and haptics.

Car-Based Marble Puzzles

Cars drive in the direction of their arrow and can block each other, so every move has to be planned.

Color-Matching Mechanics

Match each car to a marble of the same color. Every color also has its own symbol, so the game works without relying on color alone.

100 Levels, Rising Difficulty

Hand-made levels that grow harder as you go, with a skippable tutorial, unlocks, best scores and 1–3 star ratings.

Google AdMob Integration

Banner ads and a between-levels ad, shown only after the player gives consent through Google’s User Messaging Platform.

Flutter + Godot Integration

The Godot engine runs inside the Flutter app, and the two talk over a custom JSON message bridge.

Key Challenges & Solutions

Running two engines in one app

Challenge Godot’s engine can’t be restarted once it is destroyed, and its stock activity closes the whole process when it exits.

Solution Hosted Godot as a fragment inside Flutter’s activity. Leaving a level only pauses the engine, so the next level resumes almost instantly instead of cold-booting.

One source of truth for the rules

Challenge Earlier versions had the game rules written more than once, so every fix had to be made in several places.

Solution Kept a single game implementation in Godot. Flutter owns menus and saving, and the two talk through a small set of JSON commands and events.

Messages sent before the game is ready

Challenge Flutter can ask to start a level while the Godot engine is still booting.

Solution The native plugin queues commands and delivers them in order as soon as the game script reports that it is ready.

Ads that don’t interrupt play

Challenge Ads must not cover the board, shift the layout, or appear in the middle of a level.

Solution The banner lives in a fixed strip below the game view, and between-level ads follow pacing rules: never during a level, never after a loss, and never more than once a minute.

Release builds crashing on start

Challenge Code shrinking (R8) removed Java classes that Godot calls by name over JNI, so the engine aborted in release builds.

Solution Added ProGuard keep rules for the engine’s Java layer so release builds start reliably.

Keeping 100 levels solvable

Challenge With 100 hand-made levels, a small data mistake could make a level impossible to finish.

Solution Automated Godot tests validate the level data and use a simulated player to clear every single level.
